# Terrain

## How it works

An infinite LOD quadtree of chunk meshes around the camera (plus optional water mesh and collider). This folder only renders; every height and attribute comes from the height pipeline in [../../generation/](../../generation/README.md).

- [TerrainRenderer.tsx](TerrainRenderer.tsx): the chunk lifecycle, all imperative in `useFrame` (`updateTerrain`). Mounted by every `<Domain>`; `<Terrain wireframe>` draws it as lines only (no skirts, faded out by `WIREFRAME_FADE`, [../shaders/material.ts](../shaders/material.ts)).
  1. Recompute the desired set (`computeDesiredChunks`, [lod/index.ts](lod/index.ts)) after camera movement; skip the pass in steady state.
  2. Queue new/changed chunks, sorted collider LODs first then nearest-first (`prepareBuildQueue`).
  3. Build until `BUILD_BUDGET_MS`: `buildChunk` awaits the chunk's worker build and writes it into pooled geometry (`acquireGeometry`, `writeTerrainBuffers`, [chunk/geometry.ts](chunk/geometry.ts)). Far LODs throttle to `FAR_BUILD_INTERVAL_MS` while `isMachineStruggling()`.
  4. `processSwaps` swaps LODs.
  - `useLoadingGate` drives the loading bar and opens the gate (`terrainLoaded`) when the queue first drains.
- [build-requests/index.ts](build-requests/index.ts): the worker request pipeline. Keeps up to `REQUESTS_IN_FLIGHT` builds requested ahead of their turn (`prefetchQueuedBuilds`, deeper while loading), and requests a destination's chunks before the update pass gets there (`prefetchTerrainAround`, from the load and from FastTravel; a new chunk adopts its early request). [worker.ts](worker.ts) is the worker pool (its thread [terrain.worker.ts](terrain.worker.ts)) (`TERRAIN_WORKER_COUNT`, area affinity).
- [chunk/utils.ts](chunk/utils.ts): what a chunk owns — its plane (`createChunkPlane`), its water child (`ensureWaterMesh` / `releaseWater`, see [../water/README.md](../water/README.md)), its imperative Rapier heightfield on collider LODs (`generateColliders`, tagged a TERRAIN collider for the player's tunnel mode, removed in `destroyChunk`), and `syncChunkUniforms`, which writes the chunk's dither range and its blend-field clamp flag ([../shaders/material.ts](../shaders/material.ts)) before each draw. At EVERY LOD the worker's `snowDepths` whiten the chunk itself (riding `underwaterDepth` negative, [chunk/geometry.ts](chunk/geometry.ts)), so the near snow sheet never appears before the far snow vanishes.
- [lod/constants.ts](lod/constants.ts): `LOD_LEVELS` (chunk size, segments, ring distance, `hasCollider`, `skirtDepth`).
- **LOD1 sites** (`setLod1Sites` in [lod/index.ts](lod/index.ts)): points whose ring-2 chunk is drawn at LOD1 anyway out to `LOD1_SITE_DISTANCE`, for overlays standing on LOD1's drawn ground (the cave mouths, set by the underground registry); a change of the set recomputes the desired chunks.
- [lod-swaps/LodSwapper.ts](lod-swaps/LodSwapper.ts): `LodSwapper`. Old chunks stay drawn until their replacements are built, then cross-fade over `LOD_FADE_SECONDS` with complementary screen-door dither (`lodFadeDiscards`) on the discard variant (`createDiscardMaterial`, [material.ts](material.ts)); overlap tests use `ChunkIndex` ([lod-swaps/ChunkIndex.ts](lod-swaps/ChunkIndex.ts)).
- Far fade ([../shaders/material.ts](../shaders/material.ts)): the chunks whose farthest corner reaches the last 72% before `camera.far` (`chunkReachesFarFade` in [lod/utils.ts](lod/utils.ts), re-checked with every desired-set recompute) draw with the discard variant (`createDiscardMaterial`), so the horizon dithers into the sky. `TerrainRenderer` writes the live `camera.far` into the range every frame. Change the render distance through `CAMERA_FAR`, which the sky, the LOD rings and this fade all follow.
- [material.ts](material.ts) (`getMaterial`): the one terrain material — the shared vertex shader, the defines, and the fragment shader generated from every region and biome ([../shaders/README.md](../shaders/README.md)) — and its two VARIANTS, one program each, every uniform object shared: the DISCARD variant (`createDiscardMaterial`: the LOD cross-fade dither, the far fade and the tunnel openings' `discard`, [../shaders/terrain-holes/material.ts](../shaders/terrain-holes/material.ts); drawn by every chunk mid-fade, reaching the far fade, touching a hole or skirt mask, or any chunk while the player is in a tunnel, a settled chunk's dither range keeping every pixel) and the ENTRANCE variant (the cave entrance patch, `publishTerrainMaterial` / `terrainMaterialReady`). The other chunks draw the base program, which keeps its early depth test. One discard program rather than one per combination: each terrain program is ~0.6s of main-thread link in Firefox (no parallel shader compile; PERFORMANCE.md). A change of the cut set (`terrainHolesVersion`) or of the underground flag re-picks every settled chunk's material.
- **Skirts** hang below each chunk edge to hide cracks (shaded at the edge they hang from via the static `skirtDrop` attribute, so a seam shows matching ground).
- [utils.ts](utils.ts): the same pipeline on the main thread for one-off queries (`getVertexData`, `ensureVertexCompute`); frequent samples go to the dressing worker (`getVertexSample`, padded or `raw`).
- `resetTerrainSystem()` clears the module state ([store.ts](store.ts)) on domain switch. [types.ts](types.ts): `Chunk`, `TerrainState`.

Seam debugging: devmode (F1) "tint skirts" paints every skirt face magenta (`skirtTintUniform`, [../shaders/material.ts](../shaders/material.ts)) and "no LOD fade" swaps LODs in one frame (`swapper.fadeSeconds = 0`).

## How to add another

N/A — there is one terrain system; content comes from regions and biomes.

Tune: `LOD*_MAX_DISTANCE`, `LOD*_SEGMENTS`, `skirtDepth` in [lod/constants.ts](lod/constants.ts) (the outermost ring, LOD4, reaches exactly `CAMERA_FAR`), `BUILD_BUDGET_MS` in [TerrainRenderer.tsx](TerrainRenderer.tsx), and `REQUESTS_IN_FLIGHT` / `LOADING_REQUESTS_IN_FLIGHT` in [build-requests/constants.ts](build-requests/constants.ts).
