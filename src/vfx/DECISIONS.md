# Lighting and VFX — decisions

> Moved verbatim from CLAUDE.md (Oct 2026) to keep it under the context limit. Section names quoted in the text ("Blending", "Rivers", …) refer to the other decision docs listed in CLAUDE.md under "Where the docs are".

**Lighting and VFX**
- **Lamp glow uses NO real point lights** (`lighting/lampGlow.ts`): a data texture of one head per 24u cell, sampled 3×3 per fragment — constant cost for any lamp count, and it lights the UNLIT terrain. A pool of real nearest-N lights was tried and scrapped: lights visibly ignite on approach. If a lamp is rendered, its light is rendered.
- **World curvature is a VERTEX effect, never post-processing** (`vfx/curvature.ts`): bending the finished image moves pixels without moving depth, so occlusion, parallax and the horizon would disagree with the geometry. It is purely visual — physics, raycasts, placement and the height pipeline stay FLAT, and every interaction reach (doors 6u, CRT 14u) sits inside the flat zone. It works on the camera-relative VIEW position (never an absolute world coordinate) after quantization, and is applied from exactly FIVE places: the terrain vertex shader, the water shader, the foliage shader, `prepareActorMaterial`, `prepareChunkMaterial`. The sky is exempt (a dome pinned to the camera); frustum culling uses UNBENT bounds; there are no shadow casters, so no depth-pass patch exists.
- **The spawn fade is a screen door on material TWINS** (`vfx/spawnFade.ts`): materials are shared (one exterior material for every building), and three uploads a material's uniforms only when the material changes between draws, so a per-object uniform on a shared material cannot work; a fading object draws with `Object.create(base)` twins carrying their own `uSpawnFade` and reading everything else (the program cache key included — no new programs) through to the base. HAZARD: a twin must never be re-patched or have `needsUpdate` set (that forks its version from the base). GLTF clones are opaque for good (the old 1s alpha fade forced `transparent` on every clone material).
- **The nightfall hitch** (`sky/DayNightCycle.tsx`): the moon and stars first render at the exact frame dusk begins, and the lazy compile+link there (expensive under Windows/ANGLE) was a visible hitch, so the cycle `gl.compile()`s the SCENE (deferred one frame) at mount. Compiling only the celestial GROUP does NOT work: light counts are part of the program key, and a lightless subtree compiles programs the real render never reuses. `gl.compile` uses `traverseVisible`, so the day-invisible moon/stars are flipped visible for the call, and a 2-frame warm draw (moon at scale 0.001, stars at opacity 0) uploads their buffers. A post-load scene-wide re-compile was tried and REMOVED: it was itself a big synchronous hitch tens of seconds into play (streamed content is covered by `warmPrograms` / `uploadOnFirstDraw` instead).
- **The city lights are a FIXED pool of parked point lights** (`CityLights`, `world/…/city/lights.tsx`, one `cityLights` driver however many biomes mount it): a changing scene light count recompiles every lit material. Only lit materials and the terrain's point-light loop receive them.
- **Underwater is a full-screen pass, not a per-material fog** (`vfx/underwater.ts`, Oct 2026): blur needs the finished image, and a pass reading the depth buffer fogs every object class with no patch at the five curvature sites. It runs only while the camera is under water. The scene renders into a target flagged `isXRRenderTarget` with an sRGB texture: three keys a program by the target's output color space and tone mapping, so a plain target would have linked a SECOND program for every material on the first dive (the terrain's alone takes ~1s under ANGLE). Flagged, the programs are the screen's own, and the sRGB8 storage hands the pass back exactly the screen's values (the custom shaders write display values, the lit ones encode). Verified headless: fog, blur and seaweed draw (program links on the dive not yet measured).
- **Lights fade instead of switching** (`lighting/lampGlow.ts`, `CityLights`): a lamp head fades in/out over `LAMP_FADE_SECONDS` (the fade rides in the grid texel's w under the next color's threshold, so the color select is untouched); a city light fades by its distance margin to the first site outside the pool, so a re-pick only ever swaps a light at ~0 weight; an aura sprite fades by its VIEW DEPTH, because a screen-aligned sprite is clipped whole when its center crosses the camera's view plane.

- **Quantization grows with distance (Nov 2026).** Evan asked for vertex snapping that coarsens with distance, with no max distance and strong enough to read on far terrain. Past `start` the grid is `size × ((d − start) / 1km)^power`, rounded DOWN to a fixed step list, never under the base grid. First cut was linear from 200u (0.025u per u: 4u at 420u); Evan wanted NOTHING on the player's vicinity and much more on the far rings, so the overworld's curve is `{ start: 700, size: 12, power: 2 }`: untouched across the LOD1 ring (420u) and the detailed buildings (625u), 1u at 1km, 4u at 1.5km, 15u at 2km, 60u at 3km, 120u at 4km, 210u at 5km, 420u at 7km. Three devmode sliders (start, size, power). Then turned OFF by default the same day (Evan): no domain sets `quantizationGrowth`, the uniform's size is 0 and its start/power keep the tuned 700/2, so the devmode size slider alone brings it back (12 = the curve above). Steps, not a continuous size: a grid sized by the exact distance re-snaps every vertex on every camera move (the whole world swims); with steps, only the vertices crossing a band jump. Every step DIVIDES `WORLD_WRAP` (asserted at load): the terrain, water and tunnels anchor the lattice to WRAPPED coordinates and the patched materials to absolute ones, and only a divisor makes those the same lattice, so the ground and what stands on it snap together, with no seam at a wrap line. The distance is that of the UNQUANTIZED view position, so a vertex shared by two meshes (chunk edges, the sewers' duplicated join points) gets the same grid in each. Still applied ONCE, in `QUANTIZE_GLSL`, so every call site inherits it; the sprite tier stays exempt.
