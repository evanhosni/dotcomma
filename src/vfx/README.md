# VFX

## How it works

World-wide visual effects, configured once per domain through `<PostProcessing>` and applied by the class bases, never per object.

- [PostProcessing.tsx](PostProcessing.tsx): a config carrier inside `<Domain>`; props `quantization`, `curvature`, `curvatureStart`, `fpsCap`, `pixelation`, `dream`, `deepDream`, each reset on unmount. Pixelation is NOT a post-process pass: `PixelationDriver` (mounted once by CustomCanvas) lowers the canvas's pixel ratio and the browser upscales it with `image-rendering: pixelated`. The `EffectComposer` pass it replaced fought CustomCanvas's own render loop (every frame drawn twice, every program relinked, ~2 fps).
- [tuning.ts](tuning.ts): `VFX_KNOBS`, every effect's live knob for devmode's "vfx" sliders (menus/overlay/DevOverlay.tsx). Each reads and writes the effect's live value (a uniform, or a mix object the effect multiplies in: `LAMP_GLOW_MIX`, `WATER_SWELL_MIX`, `UNDERWATER_MIX`). Nothing is saved; a domain switch puts back that domain's values.
- [quantization.ts](quantization.ts) (`_quantization`): world-aligned vertex snapping of object-relative offsets (`setGridSize`, `setGridGrowth`, `QUANTIZE_GLSL`, `patchMaterial`). The grid GROWS with the vertex's horizontal camera distance past `start` as size × (km past start)^power (`<PostProcessing quantizationGrowth={{ start, size, power }}>`, three devmode sliders), in steps that each divide `WORLD_WRAP`; every caller of `quantizeWorldPos(worldPos, viewPos)` passes the UNquantized view position.
- [curvature.ts](curvature.ts) (`_curvature`): the globe illusion — vertices past `uCurveStart` sink with horizontal camera distance (`CURVE_GLSL`, `curveViewPos`). Visual only; physics and placement stay flat; the sky is exempt.
- [spawnFade.ts](spawnFade.ts) (`_spawnFade`): objects dither in (and out) with a screen-door `discard` (`SCREEN_DOOR_GLSL`) over `DURATION`. Shared materials are drawn through per-fade twin views carrying their own `uSpawnFade`. `SpawnFade`, `SpawnFadeSet`.
- [screenPass.ts](screenPass.ts) (`ScreenPassChain`, `ScreenPass`, `ScreenQuad`): THE post chain CustomCanvas's `SceneRender` draws through, in order: underwater → trace → deep dream → dream. With no pass active the scene draws straight to the screen (no target, no cost); otherwise into a target with a depth texture, then through each ACTIVE pass, ping-ponging, the last one to the screen. Every pass reads the previous pass's color and the SCENE's depth (`ScreenFrame`). Every chain target is flagged `isXRRenderTarget` with an sRGB texture so three keys every program exactly as for the screen: a plain target would have linked a second program for every material the first time a pass turned on.
- [underwater.ts](underwater.ts) (`UnderwaterPass`): while the camera is under water (`setCameraWaterDepth`, written by the Player): a wobble, a blur that widens with distance and depth-buffer fog toward the liquid's color (lit from above, darker with the camera's depth and at night). The LOOK is per liquid (`LiquidLook`, the second argument of `setCameraWaterDepth`): `water` is blue and hides ~85% by 60u; `sewage` (the sewers', from `undergroundMode`'s probe) is green, hides ~85% by 20u and blurs 2.4×. It covers every object class without patching a material.
- [dream.ts](dream.ts) (`DreamPass`, `DREAM`): a SHADER IMITATION of the early-AI dream look, `<PostProcessing dream={0–1}>` and devmode's "dream" slider; nearly free. Colors are smeared along the image's contours (a short line-integral walk on the luminance gradient, bent by drifting noise), with iridescent stripes, hue cycling and oversaturation.
- [deep-dream/](deep-dream/index.ts) (`DeepDreamPass`, `DEEP_DREAM`): REAL DeepDream, `<PostProcessing deepDream={0–1}>` and devmode's "deep dream" slider. Gradient ascent on the image to excite one layer of MobileNet v1 (`public/models/mobilenet`; only the 8.7MB of weights up to the dreamed layer are fetched, preloaded 4s after the page's load (`preloadDeepDream`) whether or not the effect is on), run by tfjs on a worker (`deepDream.worker.ts`, its own WebGL context) from the blocks' weights (batch norm folded, 1×1 convs as matMuls), not through tfjs-layers. The dream ACCUMULATES: each request reads back the previous dream reprojected onto the current view (scene depth + both cameras) blended with a little of the fresh scene, at a fixed 320×176, and takes 2 more steps; the screen shows the dream itself over the scene (overscanned 1.2×, its border fade inside the margin). Patterns grow over a few seconds and stay stuck to the world. Knobs (resolution, layer, steps, feedback, octaves) in `deep-dream/constants.ts`.
- [trace.ts](trace.ts) (`TracePass`, `TRACE`): the frozen-desktop window trail, `<PostProcessing trace={0–1}>` and devmode's "trace" / "trace stamp interval" sliders. A screen-space HISTORY (color + view distance, half-float, never reprojected) takes a STAMP of the frame every `interval` seconds wherever the frame is nearer; the live frame draws over it by the same nearest-wins rule, so anything that moves across the screen (or the whole view, turning) leaves a stack of crisp copies. Copies RECEDE (their distance grows per second, slower at higher strength) until the scene behind overtakes them; the sky never overwrites a copy, so trails across it last longest.
- [frameCap.ts](frameCap.ts): skips presented frames only (`shouldPresentThisFrame`); `isMainRenderFrame` is for render-to-texture work, never gameplay.
- [dither.ts](dither.ts): `ditherGLSL` breaks up gradient banding.
- [materialPatch.ts](materialPatch.ts): `chainMaterialPatch`, how every patcher adds its shader edit without dropping another one's (it chains `onBeforeCompile` and extends the program cache key).

Effects reach materials through `prepareActorMaterial`, `prepareChunkMaterial`, the foliage shader, and the terrain/water shaders. Each `patchMaterial` is idempotent and goes through `chainMaterialPatch`.

The sprite tier's base material (`objects/sprite-lod/material.ts`) is a call site too: it takes curvature, and deliberately not quantization (a flat billboard has nothing to snap) nor lamp glow (wrong on a far stand-in). Its fade is its own screen-door dither, complementary to the actors' spawn fade.

## How to add another

1. Create `vfx/<effect>.ts` with its uniform, GLSL and an idempotent `patchMaterial` built on `chainMaterialPatch` ([curvature.ts](curvature.ts) is the template).
2. Add a prop to `PostProcessing` that sets it and resets it on unmount.
3. Add its knob to `VFX_KNOBS` ([tuning.ts](tuning.ts)), with its `group` (`VFX_GROUPS`: screen, geometry, lighting, water), so devmode can tune it live.
4. Call the patcher from the class bases (`prepareActorMaterial`, `prepareChunkMaterial`, the foliage shader, the sprite material, unless it is wrong for a far billboard) and the terrain/water shaders — not from individual objects.

A full-screen effect (one that needs the finished image) is a `ScreenPass` instead: implement it on a `ScreenQuad` ([dream.ts](dream.ts) is the template), add it to the `ScreenPassChain` list in `world/CustomCanvas.tsx` at its place in the order, then steps 2–3.
